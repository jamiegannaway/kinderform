# Working rules for Claude Code in this repository

## Mission

Everyone who offers to care for a child deserves a quick, kind and considered reply. This repository builds free, open tools to make that true, starting with fostering enquiries in England.

## Hard rules

1. **No real personal data.** Never write, commit or log real names, contact details or records. All examples are synthetic and must look synthetic (use `example.org` addresses and obviously fictional values).
2. **Adult-side only.** No child-level data, no child-matching logic, no predictive risk models.
3. **No applicant scoring.** Do not build anything that ranks, screens or predicts people.
4. **Systems, not staff.** Any text about a service assesses the page or process. Never name individual workers.
5. **No named public scores yet.** The register holds neutral facts only. Rubric scores for named services stay out of the repository until the method has been consulted on and each service has had a right of reply.
6. **Sources and dates.** Every factual claim about a service or a statistic carries a source link and a date checked. Mark anything unverified as unverified.
7. **Do not reproduce licensed forms** (for example CoramBAAF's Form F).
8. **Polite crawling only.** Any crawler must respect robots.txt, identify itself, rate-limit to one request every few seconds per site, read public pages only and never submit a form.

## Conventions

- Schema first: change `schema/enquiry.schema.json`, then examples, then code.
- JSON Schema draft 2020-12. Field names in `snake_case`.
- Every schema change needs a valid and an invalid example in `schema/examples/` and must pass `python tests/validate_examples.py`. Monitoring records also need the semantic event checks in `schema/validate_enquiry.py`; JSON Schema alone cannot compare timestamps.
- Python 3.11+, standard library where possible. Keep dependencies few.
- British English, plain words, short sentences. Everything on the public site follows ISO 24495-1 plain language as set out in `docs/plain-language.md`, including its word list. After building, run `python tools/plain_check.py site/dist`.
- Code is MIT; everything else is CC BY 4.0. The exceptions are the ported KERN UX, DESY and NL Design System stylesheets (EUPL-1.2), the fonts (their own licences) and the Notioly illustrations (paid licence).

## Design

- **Everything uses the [shadcn/ui](https://ui.shadcn.com) design system**: its components, the new-york style, the neutral theme tokens and its typography. Add components from the shadcn registry or its GitHub source into `site/src/components/ui/`. Do not restyle them by hand or mix in another design system.
- **One exception: the questionnaire** (the reference enquiry form) uses [GOV.UK Frontend](https://frontend.design-system.service.gov.uk/) components and patterns, as set out in Decision 0001. It carries no GOV.UK branding: no crown, no GOV.UK logotype and no GDS Transport typeface. Kinderform is not a government service and must not look like one.
- **The US version of the questionnaire** uses the [U.S. Web Design System](https://designsystem.digital.gov/) (USWDS) components, built from its Sass packages in `site/src/styles/uswds.scss`. It carries no federal branding: no "official website of the United States government" banner and no identifier, which are for .gov and .mil sites only. Do not load USWDS utility classes; their names clash with Tailwind.
- **Charts use the shadcn/ui chart look**: Card with title, description and the two-line muted footer, the theme's `--chart-*` and `--primary` tokens, 4px rounded bar ends, shadcn-style legends and Progress. On the site, build them from `site/src/components/charts.tsx` (plain HTML sized with the `w-[n%]` and `h-[n%]` classes that `globals.css` generates), not the shadcn `ChartContainer`: it relies on inline styles, which the Content-Security-Policy blocks, and on client JavaScript. The SVG charts for GitHub pages (`tools/us_charts.py`) use the same neutral tokens.
- **The example forms page** (`/example-form`) is a world map that fits the screen without scrolling. Picking a country opens its form in a shadcn/ui Dialog (`site/src/components/reference-form/form-dialog.tsx`), and each country's design system loads only when its form opens (`load-<country>.ts`). `/example-form/<country>` opens that country's form directly. The map comes from Natural Earth via `tools/world_map.mjs`. The Dialog's scroll lock adds one fixed stylesheet, so the example-form Content-Security-Policy in `vercel.json` allows that one hash. If a Radix update changes it, the browser console names the new hash.
- **The Canadian and Australian versions** use the GC Design System and the Australian Government Design System. Their own components inject styles at runtime, which the Content-Security-Policy blocks, so the forms use the official tokens (`@cdssnc/gcds-tokens`, and AGDS `goldTheme` values copied with the version noted) and port each component's styles into scoped stylesheets. No government branding: no Canada wordmark or federal identity, and no Commonwealth Coat of Arms.
- **The German, French and Spanish versions** use KERN UX (the open standard for German public administration), Cunningham (an open design system from the French State's digital office, DINUM) and DESY (the open design system of the Government of Aragon). France's State design system (DSFR) may only be used by State services on .gouv.fr, and its terms cover the look of inputs and buttons, so never use DSFR code, tokens, icons, the Marianne font or its look. Spain's central system (DINTEL) is closed. As with Canada and Australia, each form's styles are ported into a scoped stylesheet (`site/src/styles/kern.scss`, `cunningham.scss`, `desy.scss`) with self-hosted fonts. No government branding: no KERN header strip (Kopfzeile) or eagle word mark (Bildwortmarke), no French State brand block or tricolour, no Aragón or Spanish government logos.
- **The Irish, Dutch, New Zealand and Singapore versions** use the Government of Ireland Design System, NL Design System components with its neutral Start theme, the New Zealand Government Design System and the Singapore Government Design System. Each form's styles are ported into a scoped stylesheet (`govie.scss`, `nl-design.scss`, `nzgds.scss`, `sgds.scss`); SGDS's own web components put styles in a shadow root at runtime, which the Content-Security-Policy blocks. No government branding: no GOV.IE header, gov.ie logo or Harp; never the Dutch central government's house style (Rijkshuisstijl), its logo or fonts, or a city's theme; no New Zealand Government logo or coat of arms; no Singapore Official Government Banner, crest or lion head. Phone examples in the wording are made up and look it (a reserved drama range where a country has one, otherwise zeros).
- **Licences of ported styles.** KERN UX, DESY and NL Design System are EUPL-1.2. Their ported stylesheets stay under EUPL-1.2, unlike the rest of the code (MIT), and say so at the top. Cunningham is MIT. Fonts keep their own licences beside them in `site/public/fonts/`.
- All the questionnaire styles stay inside the form. Everything around the form (the map, the dialog frame, the header) stays shadcn/ui.
- **Tags** use the theme's tag colours (`--tag-*` in `site/src/styles/globals.css`, through `site/src/components/tag.tsx`, a shadcn/ui Badge), chosen by meaning so a colour always says the same thing: green, checked or ready; amber, not yet checked or take care; blue, a draft or information; rose, sensitive; violet and teal, kinds of thing such as research or the law. Each pair passes 4.5:1 contrast in both themes. Charts stay neutral.
- **Legal pages** (`/privacy`, `/terms`, `/licences`) share `site/src/layouts/Legal.astro`. They use Arial and never use em dashes. When their words change, change the `updated` date. Before adding analytics, a mailing list, accounts or a form that sends data, update the privacy policy first, then the footer and the Content-Security-Policy. Contact for privacy and legal requests: jamie@kinderform.org.
- Public pages ship no tracking, set no cookies and load nothing from other sites. Fonts are self-hosted.
- **Light and dark.** Light is the default; dark applies only when the reader picks it with the switch in the header (`<html data-theme="dark">`, set by `site/public/theme.js`). Style dark mode with Tailwind's `dark:` variant, which follows that attribute, not the system setting.
- **Flags** mark the country starter kits on `/build`: square flags from flag-icons (MIT) in `site/public/flags/`, shown round in the shadcn/ui Avatar look by `site/src/components/flag.tsx`. Use civil flags without coats of arms where a country has one (Spain), so no government symbol appears.
- **Illustrations** are Notioly line drawings in `site/public/illustrations/`, used under a paid licence: they are not open, so keep only the ones the site shows and keep `LICENCE.md` beside them. Show them with `site/src/components/illustration.tsx` (decorative, empty alt, inverted in dark mode). Prepare new ones with SVGO so colours are attributes, not styles (the Content-Security-Policy blocks styles inside SVG files too). Never use drawings of children.

## Layout

- `schema/` Enquiry schema and synthetic examples; `enquiry-submission.schema.json` is what a person fills in, and `schema/ui/` holds the wording for each country's reference form (Canada also in French, `enquiry-submission.ca-fr.json`; `tests/validate_ui.py` keeps a translation in step with its main file)
- `register/` front-door registers and rules registers (`policies.csv`) for the UK, what the law in each UK nation says the assessment must cover (`assessment.csv`, checked by `tests/validate_assessment.py`; describe the law, never a licensed form), then `us/`, `ca/`, `au/`, `de/`, `fr/`, `es/`, `ie/`, `nl/`, `nz/`, `sg/`, `no/`, `dk/`, `se/` and `fi/`, with column guides; `page-dates.csv` holds the date each source page gives
- `rubric/` audit rubric in Markdown and JSON
- `census/` intake-form census: forms, questions, answer options, guidance (CSV). First-contact forms, plus application forms (`form_stage` "application", added by `tools/applications_to_census.py`) tagged with the same taxonomy so the two stages can be compared
- `evidence/` evidence library; `findings.json` is "What we know so far". Each finding's `stage` is one of the step names in `site/src/lib/steps.ts`: six steps (Ask, Reply, Route, Prepare, Apply, Stay) and one thread between them (Keep in touch). The home page, `/research` and `/for-services` all sort by those steps, so change a name there and nowhere else. The names can still change after feedback. Wherever the theme appears, its caveat goes with it: nobody has tested the steps together. `research-log.json` is the research log: one entry for each report in `reports/` and what the research could mean for the project, shown as tables at `/research/log` and linked from the site footer; run `python tests/validate_research_log.py` after editing it. Everything here except the README is published at `/research` on the site, so a merge updates the public page
- `docs/` roadmap and project notes
- `site/` public site for kinderform.org: Astro with shadcn/ui components rendered to static HTML. The only client JavaScript is `site/public/theme.js` on every page (light by default; the Light/Dark switch in the header stores a dark choice in localStorage on the reader's device, never a cookie) and the example forms at `/example-form`. `vercel.json` allows scripts from the same site only; `vercel.json` builds it. `/research` is built from `evidence/`, plus the census as unnamed patterns (`site/src/lib/forms-differ.ts`) the US register as counts with no names (`site/src/lib/us-register.ts`; summarised on `/research`, in full at `/research/united-states`), the comparison of first-contact forms across countries (`site/src/lib/countries.ts`), and first contact against the application in every country with application forms read (`site/src/lib/applications.ts`; a US application is one service's packet, and statements of what to attach are not counted as questions). "How UK enquiry forms differ" and the comparison across countries use both the census rows a person recorded and the crawler's; the form check and the rubric use only the rows a person recorded. `/compare` is for services: tables of facts that name services and places (every enquiry form, the rules in every country by topic, and the application forms in every country), each with the link, the date the page gives (`register/page-dates.csv`, built by `tools/page_dates.py`) and the date we checked, plus CSV downloads. No scores or rankings there. `/for-services` is for recruitment teams: each idea puts what the census shows (no names) next to published research and the rules, with one thing to try, plus a topic-by-topic table for checking a form (`site/src/lib/insights.ts`). `/form-check` shows the method and patterns without names. `/form-check/named` (named draft scores) is available only in local development with `KINDERFORM_PRIVATE_NAMED_RESULTS=true`; it is excluded from every static build, including previews. A preview is not an access-control guarantee. Scores are never committed
- `tests/` validation scripts
- `tools/` helper scripts: the census summary, the US register summary and charts, the polite crawler (`polite_fetch.py`; for forms built by JavaScript, `polite_render.mjs` renders the page in a headless browser under the same rules, loading only the page, its scripts and its GET data calls; both check robots.txt for every address a redirect leads to, then `polite_fetch.py --rendered` reads what it saved), and `crawl_to_census.py`, which turns crawler reads into census rows, and `plain_check.py`, which checks site text against the plain language rules

## Audit follow-up

The [26 November audit](docs/audits/2026-11-26.md) separates repaired code from independent checks still needed. Do not mark source facts or legal interpretations verified merely because tests pass. Keep claim review status attached to its exact wording. Keep pseudonymous operational records private.

## Before finishing a task

Run the tests, check that no real data slipped in, and update `docs/roadmap.md` if a milestone moved.
